# Безопасность

Коротко: публичная игра без аккаунтов и персональных данных, поэтому цель не «защитить секреты», а **не дать сайту стать
плацдармом для атаки на посетителя и не дать себя положить**. Ниже: модель угроз, что и чем закрыто, как это проверить и
чего защита сознательно не обещает.

## Модель угроз

| Кто | Что может | Что не должно получиться |
|---|---|---|
| Любой посетитель | слать любые запросы, подделывать куки и заголовки | читать файлы проекта, ломать чужие сессии, выдать себе чужой прогресс |
| Злонамеренный сайт (CSRF) | заставить браузер жертвы послать запрос в игру | изменить прогресс жертвы |
| Сетевой наблюдатель | читать и менять трафик по http | украсть куки, внедрить код (при HTTPS) |
| Нагрузка (боты, медленные клиенты) | заливать запросы, держать соединения | исчерпать память или соединения |
| Автор контента (в репозитории) | опечатка или вредная вставка в JSON | XSS через текст, клип или ссылку |

Чего в системе **нет**: паролей, почты, платежей, загрузки файлов, базы данных, чужих скриптов и шрифтов, зависимостей из npm.
Это самая сильная часть защиты: мало поверхности.

## Что закрыто и где проверено

| Угроза | Мера | Код | Тест |
|---|---|---|---|
| XSS, внедрение скриптов | CSP без `unsafe-inline`/`unsafe-eval`, `default-src 'none'`; в браузере нет инлайн-кода; весь динамический текст через `textContent` или `esc()`; клипы строятся DOM-вызовами, id проверяется и кодируется | `server/http/security.js`, `public/js/ui/dialog.js`, `ui/overlay.js` | `security.test.js` (CSP), проверено в браузере: инлайн-скрипт, чужой фрейм и чужая картинка блокируются |
| Clickjacking | `frame-ancestors 'none'` и `X-Frame-Options: DENY` | `security.js` | `security.test.js` |
| Чужие плееры и фреймы | `frame-src` только YouTube (nocookie) и Twitch clips; `sandbox` на iframe; `Referrer-Policy`, `Permissions-Policy` | `security.js`, `dialog.js` | `security.test.js` |
| MIME-sniffing | `X-Content-Type-Options: nosniff`, отдаём только известные типы | `static.js`, `security.js` | `security.test.js` |
| CSRF | куки `SameSite=Lax`; POST только `application/json` (HTML-форма так не умеет); проверка `Origin` (иначе `Sec-Fetch-Site`) | `app.js`, `respond.js`, `security.js` | `security.test.js` (кросс-сайт 403, text/plain 415) |
| Подделка куки сессии и прогресса | HMAC-SHA256 с ключом сервера; сравнение за постоянное время; формат проверяется до HMAC | `auth/session.js`, `auth/checkpoint.js` | `checkpoint.test.js`, `security.test.js` |
| Подмена одного токена другим | у каждого токена своя метка назначения (`session`, `checkpoint`), части сообщения разделены NUL | `auth/crypto.js` | `security.test.js` |
| Чтение файлов проекта (path traversal) | запрет `..`, точечных файлов, `\`, NUL; итоговый путь и `realpath` должны остаться в корне; белый список типов; авторские данные не раздаются | `http/static.js` | `security.test.js` (22 варианта атак, symlink) |
| DNS rebinding, подмена Host | белый список значений `Host`; по умолчанию сервер слушает только `127.0.0.1` | `config.js`, `security.js` | `security.test.js` |
| Перегрузка запросами | лимит запросов по адресу и классу (API / POST / статика), `429` с `Retry-After`; ограничены URL, заголовки, тело (по байтам) | `http/ratelimit.js`, `app.js` | `security.test.js` |
| Медленные клиенты | таймауты заголовков (10 с), запроса (15 с), keep-alive (5 с) | `app.js` | — |
| Рост памяти от фальшивых кук | кука длиннее 128 символов или неверной формы отбрасывается до HMAC и кэша; кэш сессий ограничен 20 000 записей | `auth/session.js` | `security.test.js` |
| Мусор в подписанном прогрессе | подписанная нагрузка всё равно разбирается осторожно: размеры, формат id, нет `__proto__` и унаследованных имён | `auth/checkpoint.js` | `security.test.js` |
| Слабый или утёкший ключ | ключ ≥ 32 байт, иначе сервер не стартует; файл `.secret` создаётся с правами `0600` и лежит в `.gitignore`; побочных эффектов при импорте нет | `auth/crypto.js` | `security.test.js` |
| Утечка деталей ошибок | клиенту только `{ "error": "код" }`, подробности в логе сервера | `app.js` | `security.test.js` |
| Вредный контент | валидатор проверяет id клипов (`[\w-]{6,64}`), http(s)-ссылки, длину текстов, известные источники и модели | `content/validate.js` | `content.test.js` |
| Цепочка поставок | **ноль зависимостей** (`dependencies` пусты), нет сборки, нет сторонних скриптов | `package.json` | — |

## Сессии и прогресс: решения

- **Сессия** это случайные 128 бит (`sid`) в подписанной куке. К IP она **не привязана**: VPN и смена сети не должны сбрасывать
  прогресс. К браузеру привязка слабая (семейство браузера и ОС), только чтобы кука не переезжала между разными браузерами.
- **Прогресс** (`cp`) подписан и привязан к `sid`, на сервере ничего не хранится. Чужая кука или подделка даёт пустой прогресс.
- Куки: `HttpOnly` (скрипты не читают), `SameSite=Lax`, `Secure` и HSTS при HTTPS (`COOKIE_SECURE=1` или доверенный прокси).
- Смена способа подписи (метки назначения) **сбрасывает** выданные ранее куки: это одноразовая цена за усиление.

## Чего защита не обещает (честно)

- **Прогресс это не граница безопасности.** Клиент сам сообщает, какие задачи выполнены; сервер проверяет порядок глав и
  полноту списка, но не может доказать, что человек «играл». Ставок нет (ни денег, ни данных), поэтому так задумано.
- Пользователь может удалить свою куку или передать её другому. Откатить прогресс на старое значение тоже можно, это безвредно.
- Лимит запросов хранится в памяти процесса. При нескольких экземплярах нужен общий ограничитель перед ними.
- TLS сервер сам не терминирует: в продакшене нужен обратный прокси (nginx, Caddy и т. п.) с HTTPS.
- Статистика сторонних сервисов и ссылки на чужие материалы приводятся как есть и помечены; их достоверность мы не гарантируем.

## Развёртывание: чек-лист

```
HOST=0.0.0.0                 # только за прокси; по умолчанию 127.0.0.1
ALLOWED_HOSTS=game.example   # ваш домен(ы), через запятую
TRUST_PROXY=1                # только если прокси ставит X-Forwarded-*
COOKIE_SECURE=1              # куки и HSTS только по HTTPS
ARCH69_SECRET=<32+ случайных байт>   # openssl rand -base64 48; храните как секрет
RATE_API=240 RATE_POST=30 RATE_STATIC=900   # запросов в минуту на адрес
```

1. Прокси с HTTPS перед приложением, HTTP на 443 не отдавать.
2. Секрет задать переменной окружения, не файлом в репозитории.
3. `npm run validate && npm test` перед выкладкой.
4. Смена `ARCH69_SECRET` разлогинивает всех (сбросит прогресс), это штатно.

## Как проверить самому

```bash
npm test                 # 44 теста, из них ~20 про безопасность
npm run validate         # проверка контента
curl -sI http://localhost:3069/ | grep -iE 'content-security|x-frame|nosniff|referrer'
```
