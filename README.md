# Истории стримеров

Интерактивные истории о стримерах: игрок ходит по комнатам (вид сверху под углом), говорит с предметами и людьми,
читает подписанные факты и смотрит клипы. Прогресс хранится в подписанной куке, файлов и базы нет.

## Запуск

Тулчейн стоит в WSL-дистрибутиве `claude`, поэтому всё запускается через него:

```bash
wsl -d claude -e bash -lc "cd /mnt/g/evrk_repo/69-project && npm run dev"
```

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер на http://localhost:3069, перезапускается при изменении `server/`, `shared/`, `content/` |
| `npm run dev:watch` | то же через нативный `node --watch`; на дисках `/mnt/*` в WSL изменений не видит, там нужен `dev` |
| `npm start` | то же без перезапуска |
| `npm run validate` | проверяет весь контент (включая шаблон) |
| `npm test` | тесты |
| `node scripts/format-content.mjs` | приводит весь JSON в `content/` к единому виду |

Управление: мышь (клик по полу и предметам), WASD или стрелки, E для действия, пробел для диалогов. На телефонах и планшетах
сами появляются экранный джойстик и кнопка E (на компьютере проверить можно, добавив к адресу `?touch=1`).

Файлы `public/` перезапуска не требуют, достаточно обновить страницу. Переменные: `PORT`, `CONTENT_ROOT` (другая папка
контента, например для черновиков), `ARCH69_SECRET` (ключ подписи, не короче 32 байт; по умолчанию создаётся в `.secret`),
`HOST` (по умолчанию `127.0.0.1`), `ALLOWED_HOSTS`, `TRUST_PROXY`, `COOKIE_SECURE`, `RATE_API`/`RATE_POST`/`RATE_STATIC`.
Модель угроз, список мер с привязкой к коду и тестам и чек-лист развёртывания: [SECURITY.md](SECURITY.md).

## Структура

```
content/                        ВСЁ, что про героев. Код сюда не лезет.
  presets.json                  общие пресеты комнат и реквизита (стул)
  streamers/
    <id>/                       один герой = одна папка
      streamer.json             имя, цвет, внешность, источники, порядок глав
      npcs.json                 повторно используемые персонажи
      chapters/*.json           главы: сцена, задачи, диалоги
    _template/                  заготовка нового героя (на сервер не попадает)

shared/grid.js                  сетка, поиск пути; один код для сервера и браузера

server/
  index.js, app.js              точка входа и сборка HTTP-сервера
  auth/                         подпись куки, сессия, прогресс (checkpoint)
  http/                         куки, ответы, статика, контекст запроса
  content/                      загрузка (loader), сокращения (expand), комната героя (home), проверка (validate), правила прогресса
  routes/streamers.js           API

public/
  index.html, css/              оболочка и стили
  js/
    main.js                     запуск и игровой цикл
    state.js                    единственное общее состояние
    engine/                     рисование, камера, ввод, движение (знает про сцену, но не про сюжет)
    game/                       задачи, взаимодействие, эфир, ход глав
    ui/                         диалоги, оверлеи, список задач

test/                           node:test
```

Старая «хакерская» версия с терминалом, версия игры до рефакторинга и разовые скрипты миграции контента вынесены из репозитория
в `G:\evrk_repo\old\69-project\` (там лежит README.txt с пояснением). Проект на них не опирается.

Правило зависимостей: `content` ← `server/content` ← `server/routes`; в браузере `engine` и `game` зависят от `state`,
но не друг от друга по кругу. Всё про конкретного героя живёт только в `content/`.

## Меню: комнаты героев

Главного меню-списка нет: игрок стоит в коридоре. У каждого героя в нём своя дверь, а над дверью табличка с его ником
(`nick` в `streamer.json`, если не задан, берётся `name`). Свободные двери до трёх подписаны «скоро» (`MIN_DOORS` в
`public/js/game/flow.js`). За дверью комната героя, в ней на пьедесталах стоят памятные вещи, по одной на главу:
- серая со замком, пока предыдущая глава не пройдена;
- светящаяся с «!», если её можно играть;
- с галочкой, когда глава пройдена (можно пройти снова).

Комната собирается автоматически (`server/content/home.js`): пресет `scenes.home` и позиции `homeSlots` из `content/presets.json`,
вещи ставятся по порядку глав. Чтобы изменить цвета или декор комнаты конкретного героя, добавьте в его `streamer.json`
поле `"home": { "floor": [...], "wall": "...", "deco": [...] }`. Глав не может быть больше, чем слотов (проверит валидатор).

## API

```
GET  /api/streamers                                  список героев и прогресс
GET  /api/streamers/:id                              герой: внешность, источники, комната (home), главы с memento и unlocked
GET  /api/streamers/:id/chapters/:cid                глава (403, пока предыдущая не пройдена)
POST /api/streamers/:id/chapters/:cid/complete       { tasks: [...] } -> открывает следующую главу
```

Прогресс: кука `cp` (`{ v: 3, p: { <streamerId>: [<пройденные главы>] } }`), подписана HMAC и привязана к сессии.
Подделка или чужая кука = пустой прогресс. Старый формат `v: 2` переносится на Дерзко.

## Как добавить героя

1. Скопировать `content/streamers/_template` в `content/streamers/<id>` и поменять `id` в `streamer.json` на имя папки.
2. Заполнить `streamer.json`: имя, цвет, внешность (`hero.look`), `sources` (ключ → подпись и ссылка), список глав.
3. Писать главы в `chapters/`. Каждый факт ссылается на ключ из `sources`, у каждого факта должен быть источник.
4. `npm run validate`. Ошибка скажет, что не так: неизвестный источник, задача, которую нельзя выполнить, недостижимый предмет,
   наложение предметов, выход за границы комнаты.
5. Перезапуск не нужен при `npm run dev`; новый герой появится на экране выбора сам.

### Формат главы

```jsonc
{
  "id": "c1", "year": 2017, "title": "Название", "intro": "Вступление",
  "tasks": [{ "id": "pc1", "text": "Сесть за компьютер" }],
  "idle": ["Реплика, если игрок долго стоит"],
  "scene": {
    "preset": "room",                         // пресет из presets.json; любые поля главы его переопределяют
    "objects": [
      { "type": "prop", "kind": "chair", "x": 1.6, "y": 2.1 },          // реквизит из presets.json
      { "npc": "kasha", "x": 3, "y": 3 },                               // персонаж из npcs.json
      { "id": "pc", "name": "Компьютер", "type": "box", "x": 1, "y": 1, "w": 2, "h": 1, "z": 0.9, "color": "#5a4a3a",
        "sitAt": { "x": 2, "y": 2.6 },                                  // герой садится сюда
        "screen": { "viewers": [0, 3], "before": { "task": "twitch", "mode": "youtube" } },
        "interactions": [{ "task": "pc1", "steps": [["h", "Реплика"], ["fact", "Факт", "blog"]] }] },
      { "id": "door", "type": "door", "x": 4, "y": 0, "w": 2, "h": 0.3, "z": 2, "requires": ["pc1"],
        "locked": [["h", "Рано"]], "steps": [["h", "Идём дальше"]] }
    ]
  }
}
```

Реплики-кортежи: `["h", текст]` герой, `["n", текст]` или `["n", имя, текст]` персонаж,
`["fact", текст, источник]` карточка факта, `["clip", текст, {type, id|slug, title}]` карточка с видео.

Шаги без текста: `["action", "Создать канал", {"hold": 1400}]` останавливает сцену, пока игрок не зажмёт круглую кнопку
(мышь, палец или пробел), а `["task", "id"]` молча выполняет задачу посреди сцены. Так вся сцена у компьютера идёт без «вставания»:
герой садится один раз, а монитор и эфир реагируют сразу после задачи.

`screen.phases` управляет монитором: список `{ "until": задача, "mode": "youtube" | "watch" | "offline" }`. Пока задача не выполнена,
показывается режим первой такой фазы; когда выполнены все, начинается эфир (чат, зрители, табличка ON AIR).

`model` объекта (`desk`, `bed`, `bookcase`, `trophycase`, `wardrobe`, `sofa`, `plant`, `bench`, `streetlamp`, `billboard`,
`noticeboard`, `speaker`) рисует объект как мебель, а не как коробку; размеры (`x y w h z`) остаются габаритами для столкновений.
`"facing": "x"` разворачивает лицевую сторону к +x (вещи у левой стены). Новую модель добавьте в `public/js/engine/furniture.js`
и в `shared/models.js`. Не ставьте высокую мебель перед дверью: валидатор проверит достижимость, но не загораживание обзора.

`memento` главы (`name`, `glyph`, `color`, `text`) обязателен: это памятная вещь героя, которая стоит в его комнате и открывает главу.

Задача выполняется, когда игрок прошёл взаимодействие с `task`. Счётчик (`"needs": {"prefix": "npc_", "count": 3}`)
выполняется, когда сделано нужное число задач с этим префиксом. Дверь с `requires` открывается после этих задач, а её `task`
выполняется при выходе.

## Принципы контента

- Факты только из источников, у каждого факта ссылка. Неофициальная статистика помечается в подписи источника.
- Реплики героя и персонажей вымышленные и лёгкие; живым людям не приписываются мнения, оценки и события.
- Личная жизнь, здоровье и семья в игру не попадают; конфликты и обвинения тоже.
- Клипы чужие и встраиваются как есть; права принадлежат авторам, рядом всегда ссылка на оригинал.
